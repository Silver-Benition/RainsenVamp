# Session 9 · 复盘与隐患记录

> **本次性质**：从“敌人能受击”扩展到玩家生命、实体接触和完整单局结束流程。
> **日期**：2026-08-20

## 一、架构结论

### 1. IDamageable 扩展到玩家后，攻击方必须同时表达阵营

IDamageable 只回答“对象能否承受伤害”，不回答“谁可以伤害谁”。玩家实现该接口后，如果武器继续对任意 IDamageable 结算，就会产生己方投射物误伤玩家的问题。

本次通过 DamageTargetFilter 把 Player/Enemy Layer 过滤集中起来，并兼容 Collider 位于子节点、接口位于刚体根节点的 Prefab。五类武器统一只寻找 Enemy，EnemyBase 统一只寻找 Player。后续如果增加召唤物、中立物、友军或阵营变化，不应继续堆叠零散 Tag 判断，而应把阵营关系升级为明确的 Faction/DamageTeam 规则。

### 2. 生命逻辑、受击表现和 UI 应由事件解耦

PlayerHealth 只决定生命、无敌窗口和死亡；PlayerDamageFeedback 只处理染色；PlayerHealthBarUI 只处理显示。Damaged、HealthChanged 和 Died 三个事件使这些表现可以独立替换，不需要让 PlayerHealth 直接操作 SpriteRenderer、Slider 或 Game Over 面板。

该边界也为未来护盾、受击音效、屏幕震动、低血量提示和角色语音保留了扩展点。新增表现应订阅结果事件，不应反向改变生命逻辑。

### 3. 当前接触伤害是离散无敌帧模型，不是连续 DPS

EnemyBase 在 OnCollisionStay2D 中持续请求伤害，但 PlayerHealth 以 0.5 秒全局无敌帧过滤请求。它的优点是规则简单、多个敌人同帧接触不会瞬间清空生命；缺点是敌人数增加时伤害上限仍主要由全局无敌时间决定。

如果后续切换到《吸血鬼幸存者》式连续掉血，不能只把 invulnerabilityDuration 设为 0。当前 collisionDamage 为“每次伤害”，若每个 FixedUpdate 直接扣 10，会产生极高且依赖物理步长的 DPS。正确备选方案应：

1. 把配置语义改为 collisionDamagePerSecond。
2. 每个物理步按 `damagePerSecond × Time.fixedDeltaTime` 累计。
3. 明确多个敌人接触时是完全叠加、设置上限，还是按最高接触源结算。
4. 让逻辑扣血可以高频发生，但单独限制染色、音效和屏幕震动频率，避免每物理帧重启表现协程。

该方案本次只作为预备设计记录，没有实现。

### 4. Dynamic Rigidbody2D 能快速获得自然分离，但需要性能预算

EnemyBase 从 MovePosition 改为写入 velocity 后，Physics2D 可以处理敌人之间、敌人与玩家、玩家与掩体之间的实体接触。零摩擦、零弹性材质降低卡死和弹飞；对象池出入时清速度避免旧动量复用。

这一方案非常适合当前 MVP，可直接解决敌人完全重叠问题。但 Survivor-like 的最终敌人数可能远高于普通动作游戏。大量 Dynamic Rigidbody2D 与全连接接触对会显著增加 Physics2D 成本。是否需要空间哈希、邻域推开、分层 Collider 或数据导向模拟，必须以目标规模下的 Profiler 为依据，不能只凭当前少量敌人的流畅表现判断。

### 5. 提高玩家质量是抗挤压手段，不是绝对不可推动规则

玩家 Mass 50、敌人 Mass 1 会让接触求解更偏向移动敌人，老大已验证玩家贴近掩体时不再容易被敌人推入缝隙。但质量并不等于锁定位置；足够多的敌人、狭窄几何和极端速度仍可能施加位移。

如果未来设计要求“敌人永远不能推动玩家”，应采用更明确的运动约束或分离策略，而不是无限提高质量。当前方案保留物理接触感，同时满足本阶段体验。

### 6. 暂停必须保存原因，而不是让每个界面直接写 Time.timeScale

升级选择、手动暂停和 Game Over 都需要冻结游戏。如果每个系统各自把 Time.timeScale 在 0/1 之间切换，关闭某个面板可能错误恢复仍应暂停的游戏。

GameFlowManager 通过 PauseReason 位掩码集中协调所有暂停来源。只有原因集合为空时才恢复时间。LevelUpManager 保留缺少管理器时的测试场景回退，但 MainLevel 已使用统一流程入口。未来设置菜单、剧情暂停或应用失焦暂停也应新增原因，而不是直接覆盖 Time.timeScale。

### 7. 像素角色的“视觉中心”不能由通用几何 API 决定

本次血条定位先后评估了：

- Player 根节点/Pivot。
- SpriteRenderer.bounds.center。
- Tight Mesh 顶点左右边界中心。
- Alpha 包围盒和 Alpha 重心。

这些方法最多得到矩形中心、渲染包围中心或像素质量中心，无法理解头部、躯干、武器、披风和装饰的语义权重。动画帧变化还可能让自动中心轻微抖动。最终采用每个角色一个 HealthBarAnchor：策划或美术只需配置一次，运行时成本近乎为零，结果也最稳定。

该经验不只适用于血条。名字、状态图标、锁定标记、受击数字和脚底特效等角色跟随 UI，都应优先考虑显式挂点，而不是猜测 Sprite 几何中心。

## 二、世界线碰撞问题

WorldEnemySimulation 在世界线隐藏时会关闭该世界敌人的 Collider 和 Renderer，但不会暂停 EnemyBase 或 Rigidbody2D。隐藏敌人仍朝玩家移动，却失去敌人之间的实体接触，因此可以在后台重叠。切回该世界时 Collider 同帧恢复，Physics2D 会集中解决穿透，形成短暂爆散。

这个问题可以实现优化，但不是“免费让隐藏世界继续碰撞”这么简单：

- 保持 Collider 全开会让隐藏世界继续参与玩家、掩体和另一世界的碰撞，需要额外 Layer/PhysicsScene 隔离。
- 使用独立 PhysicsScene2D 可以完整模拟，但架构和成本更高。
- 隐藏时运行自定义低频邻域分离可以降低成本，但会新增模拟路径。
- 激活前做一次位置预分离最便宜，但切换瞬间仍需要保证不穿掩体和玩家。
- 限制隐藏世界在场敌人数或生成密度是策划层面的低成本缓解手段。

本次明确选择不扩大范围，先保证单一激活世界的表现。该问题应在世界线系统进入正式性能设计时统一处理。

## 三、本次迭代经验

- 在接口能力扩展前先检查所有调用方。给玩家添加 IDamageable 看似局部，实际会影响所有武器命中入口和弹射搜索。
- 物理接触问题必须同时检查 Rigidbody 类型、移动 API、Collider 数量、材质、质量和碰撞检测模式，只改一个参数往往不能得到稳定结果。
- Player 根节点应尽量保持逻辑中心；表现偏移交给 Visuals 或显式 Anchor，避免为某个 UI 修改角色根坐标。
- 像素 UI 的清晰度依赖整数尺寸、PPU、Pixel Perfect、整数 Slider 档位和整像素位置共同成立。
- 游戏结束不是简单显示一个面板，还必须停止玩家输入、清速度、处理其他面板和恢复重开前的 Time.timeScale。
- 运行验证必须覆盖交互组合：升级暂停、手动暂停和死亡不能只单独测试。
- 自动算法如果无法表达设计语义，应及时停止复杂化，改用清晰的美术/策划配置点。

## 四、未完成与风险

1. 连续接触 DPS 仍是备选方案，尚未决定多敌人叠加规则和表现节流方式。
2. 隐藏世界线敌人 Collider 关闭后会重叠，重新激活可能爆散。
3. 当前玩家与敌人使用 Dynamic Rigidbody2D；最终同屏规模下的 CPU 和接触数量未知。
4. HealthBarAnchor 目前直接存在 MainLevel 的 Player 层级中；正式多角色系统需要把它纳入角色 Prefab 规范。
5. Pause/Game Over 文案和按钮尚未接入本地化，也没有动画、音效、结算或返回标题流程。
6. PlayerHealth 的最大生命尚未与 PlayerStats 或角色数据资产打通。
7. 全局无敌帧意味着多敌人同时接触不会线性增加伤害；这是否符合最终战斗设计尚未定案。
8. 五武器 Lv.1/Lv.5 完整回归继续暂缓，不能因 Session 9 功能通过而视为已验证。

## 五、后续方向

### MVP 回归

- 建立玩家受击测试矩阵：单敌人、双敌人、包围、贴掩体、暂停中受击、升级瞬间和死亡瞬间。
- 完成五把武器 Lv.1 / Lv.5 的固定回归记录。
- 验证 HealthBarAnchor 在左右转向、不同角色尺寸和不同动画中的稳定性。

### 工程完善

- 为 PlayerHealth 伤害过滤、死亡单次事件、GameFlow 暂停原因组合增加自动化测试。
- 设计并原型验证连续 DPS 模型，但在替换当前无敌帧方案前重新确认策划规则。
- 为世界线后台敌人选择 Collider 隔离、低频分离或激活前预分离策略。
- 把角色生命、受击反馈、碰撞体和 UI 锚点整理为正式角色 Prefab 模板。
- 建立 Physics2D Profiler 场景，记录 50/100/200/500 敌人的 FixedUpdate、接触和 GC Alloc。

### 长期扩展

- 引入角色属性、防御、护盾、治疗、复活和受伤倍率。
- 建立阵营/伤害队伍系统，支持召唤物、中立单位和友军。
- 完成局内结算、返回标题、重新开始确认和暂停设置菜单。
- 当物理成本达到瓶颈时，评估空间划分与自定义群体分离替代完整刚体接触。

## 六、Session 结论

Session 9 补齐了玩家从“可移动攻击”到“会受伤、会死亡、可暂停和可重开”的最小单局闭环，同时让敌群从完全重叠升级为具有实体体积的追踪群体。玩家生命、表现、UI 与游戏流程已经解耦，暂停也有了统一原因管理。当前最主要的后续风险是 Dynamic Rigidbody2D 在目标敌人数下的性能，以及隐藏世界线 Collider 关闭导致的后台重叠；两者均已明确记录，不阻塞下一阶段开发。
