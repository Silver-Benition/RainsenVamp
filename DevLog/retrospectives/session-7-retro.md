# Session 7 · 复盘与隐患记录

> **本次性质**：双世界 MVP 收尾。
> **日期**：2026-08-18

## 一、架构结论

### 1. 世界波次必须属于世界运行上下文

将 `WorldWaveManager` 挂在每个世界运行节点下，使计时、规则积分和 alive 计数天然隔离。`WorldLineCoordinator` 只负责世界归属和表现/交互状态，不承担刷怪细节。

### 2. 对象池回收通知必须带世界归属

同一个敌人 Prefab 可以被多个世界复用，因此回收通知不能只绑定全局 `WaveManager`。当前 `WaveSpawnedNotifier` 支持旧波次管理器和世界波次管理器两条路径，避免计数串线。

### 3. 可观测性先于性能判断

双方敌人数和波次时间进入调试 UI 后，才能判断副世界是否持续推进、数量上限是否释放，以及不同世界的节奏是否真的不同。当前 UI 是开发工具，不参与玩法逻辑。

## 二、工程经验

- Unity 场景 YAML 手写配置容易出现“组件块存在但未加入 `m_Component` 列表”的问题，必须同时检查组件块和 GameObject 组件列表。
- Unity 编译验证必须在项目锁释放后执行；批处理实例不能和已打开项目的 Editor 并行运行。
- C# 编译错误应优先读取 Unity Editor 日志中的第一条 `CSxxxx`，不要仅凭静态文件检查判断完成。
- 两个世界目前共用敌人 Prefab，但已通过独立 WaveConfig 验证了节奏差异。

## 三、当前风险

1. 当前两个世界的敌人逻辑仍然运行两份，实体数量扩大后需要 Profiler 验证 CPU、Physics2D 和 GC Alloc。
2. 副世界敌人仍不处理自身掩体路径，当前 MVP 只关闭副世界碰撞表现。
3. 世界状态尚未快照化，敌人、掉落物和波次状态依赖活对象持续存在。
4. 调试 UI 使用运行时字符串格式化，当前规模可接受；大规模或正式版本应提供开关或移入开发构建。
5. 世界线资产仍保留历史测试敌人字段，当前运行入口已改为正式波次，后续可在独立清理任务中删除旧字段。

## 四、后续方向

双世界 MVP 现阶段不继续扩张。优先优化玩家移动、武器手感、经验升级和升级选择流程；待敌人池和规模扩大后，再建立 30/60/100 敌人压力下的 Profiler 基线。
