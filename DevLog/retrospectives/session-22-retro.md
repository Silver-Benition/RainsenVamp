# Session 22 复盘：局外成长的数据边界与商店交互

- 日期：2026-09-13。
- 结果：三页签商店、配置化成长、金币买退、封印迁移和启用偏好完成；独立 Review APPROVED，老大确认本轮无问题并要求归档。

## 关键决策

1. 用累计等级快照定义成长，逐级实付历史定义退款，启用偏好另存。三者分离后，变价、降上限、停用和退到零都不需要猜测或丢弃玩家权益。
2. 账号交易先复制候选、持久化成功后发布，UI 只调用服务并反馈结果。金币、购买记录、索引和 Changed 不能分步更新；保存失败时勾选同样恢复真实状态。
3. 局外成长在首次属性读取前建快照。这样最大生命与每局次数都从正确初值开始，旧玩家快照不会因菜单偏好修改而变化，角色和局内来源也不受误删。
4. “放逐”和“封印”保留独立含义。用户澄清后仅更名封印，不合并 ID、购买等级或货币；封印/重投/跳过/放逐无需开关，玩家自然决定是否使用。该例说明同名或近义功能应先核实消费范围。
5. UI 大区块以几何图为准，卡片内部以竞品图为准。先明确图标框、等级格、价格、详情和锁定边框，再实现三列布局，避免只复制分区却遗漏信息结构。
6. 当前累计值和本次增量分开展示，百分比文案与实际修改器同步核对。Defang 的 Flat 是概率，不能因为显示 `%` 就改为乘法；移速/磁吸则按批准范围真实转为百分比。

## 真实发现与修复

- **R-01 主菜单不可达**：旧显式导航环仍只有三个按钮，方向操作跳过新商店。修复场景与作者工具，并从默认焦点通过真实 Move/Submit 验证入口及返回。
- **R-02 向上半卡裁切**：ScrollToEntry 把 pivot 坐标当顶部。独立审查指出后，新测试在旧代码上于两分辨率复现卡片超视口 52 画布单位；修复为真实 top，使用世界四角转视口空间的独立断言验证浏览/锁定状态往返，不复写生产公式充当测试。
- **Toggle 刷新失焦**：刷新时先禁用再启用控件会使 EventSystem 清空选择。真实测试发现预期 Toggle 实际 null；改为计算最终状态后一次应用，保留切换后的焦点断言。退款隐藏也检查当前控件是否仍有效。
- **勾选淡出歧义**：默认动画使关闭瞬间仍像开启。使用即时勾选显示并检查图形 alpha，让开关视觉与保存状态一致。
- **同帧重复输入**：轮询 Cancel 和 ICancelHandler 共用同帧去重；锁定当帧拒绝交易，防止一次确认就扣款或一次取消退出两层。

## 验证与协作经验

初版 D-01 辅助截图存在静态批次漏绘，没有将残缺图片算作视觉通过。后续在测试中先配置固定尺寸相机再显示页面，等待完整渲染，得到完整的 1080p/720p 截图；不为截图改生产相机或编辑图片。自动化仅在内存/临时目录账号运行，真实用户存档不作测试材料。

独立审查使用真实 Diff、场景/Prefab、报告 XML 和截图，而不是复制 Execute 的完成总结。增量返工复用原任务和分支，问题修复后只复审相关增量；最终 main 快进后再跑项目要求的完整门禁。QA 160/160 与 63/63 是既有最终实现证据，main 的同数新报告是归档集成证据，二者不互相替代。

桌面任务摘要曾未及时更新，实际执行仍在推进；协调任务通过本地会话和交付包确认事实，没有误判为停工或启动第二个写入者。一次跨任务进度发送被自动审批以目标可信性未验证拒绝，改为本地交付读取，不借此修改应用私有状态。任务实际模型/推理档位无法核实时保持 unknown。

三轮用户反馈分别修正布局、文案、语义与开关范围，新增持久化明确重新确认后才写入。最后用户的“无问题、执行归档”作为本轮验收关闭依据，不扩写为所有设备和输入组合均人工实测。
