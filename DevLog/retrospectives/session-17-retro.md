# Session 17 复盘：能力内容、单局状态与机制运行时必须分层

- 日期：2026-08-31
- 主题：正式能力数据、稳定修正来源、事件驱动机制、非分配范围伤害和局内/账号边界。

## 本次最重要的架构决策

### ScriptableObject 描述内容，AbilityManager 持有单局状态

能力名称、图标、等级快照和机制类型适合由 `AbilityDataSO` 配置；当前等级、冷却、激活状态和事件订阅不适合写入共享资产。本次将单局拥有状态集中在玩家 `AbilityManager`，使真实场景重开自然清空能力，也避免多个运行实例互相污染。

### 累计等级快照配合稳定来源替换

每级能力数据描述“升到该级后的最终累计效果”，而不是只描述本级增量。`AbilityManager` 使用 `ability:{id}:base` 替换同源修正，因此无论升级顺序或 UI 重绘次数如何，都不会把前一级重复叠加。

机制动态效果使用独立的 `ability:{id}:mechanic` 来源。传统基础效果和条件效果互不覆盖，使未来一个能力同时拥有常驻数值与触发机制时仍能保持可预测性。

### 机制 SO 是工厂，运行时对象才保存状态

`AbilityMechanicSO` 只负责创建 `IAbilityMechanicRuntime`。低血量激活标记、反击冷却和事件订阅全部属于运行时对象，销毁能力管理器时统一释放。这个边界允许共享同一能力资产，同时保持每局、每个玩家状态独立。

### 高频机制优先事件驱动和非分配查询

逆境本能响应 `PlayerHealth` 事件而非每帧检查。反击脉冲只在实际受伤时执行一次 `Physics2D.OverlapCircle`，使用固定 Collider 缓冲区和复用 HashSet，不在常态帧循环或每个敌人上新增监听。

同一敌人的多个 Collider 必须先解析为 `IDamageable` 后去重，否则范围能力会因 Prefab 物理结构不同而重复造成伤害。

## 系统边界教训

### 正式能力不等于角色天赋，也不等于账号进度

角色固有被动是角色身份的一部分，不占用能力槽；正式能力是单局升级选择；Seal/Banish 等持久行为仍属于账号系统。三者可能共同影响升级候选，但不能共享状态容器或存档生命周期。

### 武器与能力可以共享升级卡片，不应共享全部奖励入口

`UpgradeDataSO` 通过 XOR 契约确保一张升级卡只代表一种奖励，UI 再根据奖励权威数据渲染。普通升级候选可以混合武器与能力，但宝箱的设计语义仍是武器成长，因此本次明确保持武器专属路径。

### 真实重载测试比只销毁临时对象更有价值

单元测试可以证明 `AbilityManager` 销毁时清理来源，但不能证明 MainLevel 序列化绑定和游戏重开链路。PlayMode 测试必须先在真实场景授予能力，再调用正式重开流程，并在新场景断言能力归零。
