# Session 27 复盘：从原版证据到可验收的项目实现

日期：2026-10-04。对应 [进度归档](../progress/session-27.md)、[代码变更](../code-changes/session-27-changes.md)。

## 关键决策

1. 以用户本地 Brotato 1.1.15.4 安装包为机制依据，先确认版本和包指纹，再恢复相关脚本/资源。教程、计算器和第三方仿作无法证明原作左右挥击和节点运动；恢复代码本身也有字节码回退限制，不能冒称公开源码或运行结果。
2. 原版查证扩展到全部核心玩法，但实施分批推进。近战先解决运动模型与两种计时，再处理共享数值/获取，最后根据试玩补标签、降低起手压力和完善战斗信息。查证范围不等于全部复刻授权。
3. 近战动作与冷却必须一起计算。把冷却赋值和冷却推进混为一谈，会让动作正确却攻速收益错误；面板也必须遵守相同参考公式。固定刀身、移动握柄和目标生命代次是明确契约。
4. 武器偏好依据稳定标签而非伤害系数，标签计数依据持有实例而非品质。羁绊是当前档总收益；同类型多副本、重复标签、合成后的件数减少必须同时考虑。
5. 降压采用逐敌种波次成长，取消重复的全局生命/伤害叠乘；保留原有密度和 Boss 独立配置。先保证起手顺畅，不把低压配置宣称为原作全部难度平衡。
6. 复用既有伤害快照增加实例账本，避免每次命中查找组件或按武器名称混账；波次令牌拒绝延迟回执，Boss 结果收口前入账，合成明确保留两把材料贡献。
7. 按用户参考把全部羁绊档位放到右侧浮层，库存伤害使用独立窗；显示回收报价时共用实际交易入口。信息布局与数值来源分别承担职责。

- 单点截图不能证明完整挥击；前期近战补了左右连续轨迹、回收与八方向检查。图形测试和主 Agent 看图仍不代替用户手感验收。
- 长 Session 的各轮报告必须保留时间边界。四轮文件记录按新覆盖旧合成最终 120 文件清单，并逐字节核对，才能复用已通过的完整门禁；不能只核对最后 25 文件就代表整个 Session。
