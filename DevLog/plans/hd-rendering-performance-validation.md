## 触发条件

满足以下任一条件时，应立即执行本待办：

2. 准备第一次对外试玩或低配目标设备验收。
3. 运行中出现与敌群密度、透明 Sprite 重叠或水晶球冻结蒙版相关的持续掉帧。

## 验收范围

在目标平台的 Development Build 中，以固定分辨率和质量档执行：

1. 普通场景基线。
2. 最大目标敌群密度。
3. 经验与金币大量堆积后集中磁吸。
4. Boss、敌方弹幕与玩家武器同时活跃。
5. 上述高密度状态叠加水晶球 15 秒冻结蒙版。
6. 两条世界线分别复测。

记录 CPU Main Thread、GPU Frame Time、Batches、SetPass Calls、GC Allocated In Frame、Gfx Used Memory 与 Texture Memory，并以目标帧率的帧预算作最终判断。

## 已确认决策

- 高清画质是正式美术方向，不把恢复低像素中间画布作为默认性能解决方案。
- 若性能不达标，优先通过 Profiler 与 Frame Debugger 定位 CPU、透明 Overdraw、批次、材质、对象池和全屏蒙版成本，再进行针对性优化。
- 动态分辨率、降低内部渲染分辨率或恢复低清版本只作为最终兜底候选；除非老大在看到性能证据后重新明确批准，否则不得实施。
- 本待办完成前，只能将高清渲染记为“静态画质通过、规模性能待验”，不能宣称最终性能验收通过。

## 完成条件

1. 使用具备代表性的正式敌群规模完成 Profiler 录制。
2. 最坏场景没有持续超过目标帧预算，且内存不存在随重复拾取或冻结持续增长的趋势。
3. 若曾发现瓶颈，已完成针对性优化并重跑相同场景。
4. 保存测试环境、关键指标和结论，归档到当期 Session DevLog。
